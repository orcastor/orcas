OrcaS v0.2.0 加强认证与访问控制，修复并发批量写入和日志读取问题，并优化目录缓存与 SQLite 元数据查询。本版本包含部署配置变化，升级前请检查下列迁移说明。

## 安全加固

- S3 请求必须通过 AWS Signature V4 或 JWT 认证，移除跳过验签和匿名管理员回退；修正 AWS 正文摘要、时间、规范化请求与签名校验。
- JWT 仅接受 HS256，并验证签发者、有效期和用户 ID；令牌仅从 `Authorization` 请求头读取，避免认证缓存延长令牌有效期。
- 从当前数据库验证用户角色与权限，降权、删除用户和撤销 ACL 立即生效；删除用户时事务清理 ACL。
- 新密码使用带随机盐的 PBKDF2-HMAC-SHA256；旧 SHA1 密码哈希在成功登录后自动升级。
- 增加 SQL 排序字段白名单、请求正文和列表大小限制、HTTP 读取超时，以及精确来源 CORS 白名单。
- SDK 下载限制路径与符号链接逃逸，等待并发下载完成并返回写入、刷盘和关闭错误；新建存储文件与目录使用私有权限。
- 更新 JWT、Gin、gRPC、Protobuf、OpenTelemetry、WebSocket 和 Go 扩展依赖。

## 存储与性能

- 重构小文件批量写入，串行化刷盘并保护缓冲区所有权；失败时保留待写数据，读取返回独立快照，空闲时释放缓冲区。
- 定时刷盘不再受单次请求取消影响；S3 写入在数据与元数据持久化完成后才返回成功。
- VFS 数据和目录缓存同时受字节预算与条目数量限制；目录快照保持不可变，并通过名称索引加速查找，防止并发失效后重新发布旧缓存。
- 为日志重叠写入建立区间索引，按最新写入覆盖读取结果，并保留稀疏区域与旧日志读取兼容性。
- 增加目录分页与数据引用索引，已有桶首次打开时自动补建；内部遍历可跳过无用的总数查询。
- 去重查询在同一 SQLite 物理连接内创建、查询和清理临时表，修复连接池下的并发查询问题。
- CLI 用户与桶管理复用同一配置、数据库路径和密码输入，管理命令不再要求上传或下载路径。

## 升级说明

- Go 模块最低要求 **Go 1.26.10**，默认工具链为 **Go 1.27.3**。
- 新数据库首次启动必须显式设置 `ORCAS_ADMIN_PASSWORD`，用于创建 `orcas` 管理员；已有账号和密码不会重置。已有部署如仍使用默认密码，应主动修改。
- RPC 服务要求 `ORCAS_SECRET` 至少 **32 字节**。使用 JWT 的 RPC 与 S3 实例应共享同一密钥；更换密钥会使旧令牌失效。
- JWT 调用方应使用 `Authorization: Bearer <token>`，不再支持 URL 或表单中的令牌。使用 `ORCAS_SKIP_SIG_VERIFY` 的客户端必须改为正常签名。
- 跨域浏览器访问需通过 `ORCAS_CORS_ORIGINS` 配置精确来源列表；默认仅允许同源请求。
- RPC 正文上限为 **1 MiB**，列表上限为 **1000**；S3 单次请求默认上限为 **64 MiB**，可通过 `ORCAS_MAX_REQUEST_BYTES` 调整，或使用分片上传。S3 正文仍会读入内存，需结合并发量设置上限。
- 原有压缩数据和旧密码哈希保持读取兼容；已有文件权限不会自动修改。

配置与迁移细节见[安全加固文档](https://github.com/orcastor/orcas/blob/v0.2.0/docs/security-hardening.md)。

## 下载与验证

提供 Linux **amd64**、**arm64** CLI 压缩包及 `SHA256SUMS`。每个压缩包包含可执行文件、许可证、中英文 README 和示例配置。

```sh
sha256sum -c SHA256SUMS
go get github.com/orcastor/orcas@v0.2.0
```

发布流程在两个原生 Linux 架构上构建并编译所有测试包，执行带竞态检测的 SDK、安全、压缩兼容性、VFS、批量写入、缓存、日志索引及 SQLite 回归测试。发布检查范围与历史完整测试集的限制见 [CI 文档](https://github.com/orcastor/orcas/blob/v0.2.0/docs/ci.md)。

## English

OrcaS v0.2.0 hardens S3/JWT authentication, current-database authorization, password storage, request limits, CORS and SDK download paths. It also fixes concurrent batch persistence, bounds VFS caches, indexes overlapping journal writes and improves SQLite pagination and pooled deduplication queries.

Before upgrading, use Go 1.26.10 or newer (selected toolchain: Go 1.27.3), set `ORCAS_ADMIN_PASSWORD` when initializing a new database, and configure a JWT secret of at least 32 bytes. Send JWTs through the `Authorization` header, configure exact cross-origin origins when needed, and account for the default 64 MiB S3 request limit. Signature-verification bypasses are removed. Existing accounts, legacy password hashes and compressed data remain compatible; legacy hashes upgrade after successful login.

Linux amd64 and arm64 archives and SHA-256 checksums are included. The release workflow builds both native architectures and runs the focused race-enabled release gate; it does not run the entire legacy integration, mount and stress suite.
