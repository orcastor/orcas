# 安全加固与验证

验证日期：2026-10-30。范围包括 RPC、S3 认证、核心权限与账号管理、SDK 下载、存储权限和 Go 依赖。

## 已修复的问题

| 问题 | 修复后的行为 |
| --- | --- |
| S3 跳过验签、匿名继续执行、默认使用管理员身份 | 移除 `ORCAS_SKIP_SIG_VERIFY` 分支；每次请求必须通过 AWS V4 或 JWT 认证，认证只设置用户 ID |
| 管理员角色可从上下文或跨数据库缓存获得 | 从当前数据库读取角色；降权、删除用户后立即失去管理权限 |
| 删除用户后遗留 ACL 仍能授予访问权 | 事务删除用户及 ACL，权限查询同时要求用户存在；S3 桶列表重新读取 ACL |
| 空密钥 JWT、算法与声明检查不足、缓存延长令牌有效期 | 密钥至少 32 字节，仅允许 HS256，要求有效期、签发者和正数用户 ID；逐次验证，不复用认证缓存 |
| JWT 出现在 URL 或表单中 | 仅从 `Authorization` 请求头读取，支持 `Bearer <token>` 和原有纯令牌格式；限制令牌长度 |
| AWS 正文可被篡改、时间检查未生效、错误泄漏签名计算细节 | 校验正文 SHA-256、严格检查时间及 15 分钟偏差、凭证范围、签名字段和所有 S3 操作头；常量时间比较签名；外部错误不包含计算结果 |
| AWS 规范化与并发凭证存储问题 | 修正多余换行、查询编码与排序、Host 端口处理；凭证存储加锁并复制传入、返回的凭证 |
| 自动创建固定密码管理员、弱密码哈希 | 新库必须显式设置引导密码；PBKDF2-HMAC-SHA256、600000 次迭代、随机盐；旧 SHA1 格式在成功登录后升级 |
| 用户密码、角色更新失败 | 修正更新方法多传一层指针的问题；旧哈希升级使用条件更新，避免覆盖并发密码重置 |
| 排序字段直接进入 SQL | 普通列表与回收站列表只接受排序字段白名单，拒绝 SQL 表达式与多字段输入 |
| 任意来源的凭据式跨域访问 | 默认只允许同源请求；跨域使用精确来源白名单，不反射任意来源，也不发送凭据许可 |
| 无限制正文、错误 JSON 继续执行、过大列表 | RPC 正文上限 1 MiB、列表上限 1000；S3 正文默认上限 64 MiB；同时限制未知长度的流；解析失败立即停止 |
| 慢速 HTTP 请求长期占用连接 | 请求头默认 10 秒，完整请求默认 2 分钟；配置文件可调整正数超时 |
| SDK 下载路径与符号链接逃逸、异步下载错误丢失 | 校验远端名称为单个文件名，使用 `os.Root` 限定写入范围；等待所有下载并返回写入、刷盘及关闭错误 |
| 新建数据库与数据文件对其他用户可读 | 新文件使用 `0600`、新目录使用 `0700`；SQLite 日志继承数据库权限 |
| CLI 账号管理无法正确使用自定义目录或标准输入密码 | 登录与管理操作使用同一组数据库路径；只加载一次配置和密码；管理命令不再强制要求本地文件路径 |
| 已知依赖漏洞 | 升级 JWT、Gin、gRPC、Protobuf、OpenTelemetry、WebSocket 及 `golang.org/x/*` 依赖；选用 Go 1.27.3 工具链 |

## 部署配置变化

- 模块最低 Go 版本为 **1.26.10**，`go.mod` 选择 **1.27.3** 工具链；CI 已使用该版本。
- 新数据库首次初始化必须设置 `ORCAS_ADMIN_PASSWORD`，用于创建用户名为 `orcas` 的管理员。保存到密码管理器，初始化后可移除该环境变量。已有账号不会被重置；旧部署的默认密码需要由管理员主动修改。
- RPC 启动要求 `ORCAS_SECRET` 至少 32 字节。可以用 `openssl rand -hex 32` 生成，安全保存并在 RPC、S3 实例之间使用同一密钥。更换密钥会使旧 JWT 失效。仅使用 AWS 认证的 S3 服务可以不配置 JWT 密钥。
- 浏览器跨域访问设置 `ORCAS_CORS_ORIGINS`，例如 `https://storage.example.com,https://admin.example.com`。不接受 `*` 或 `null`。同源请求无需白名单；TLS 在反向代理终止时，可显式配置浏览器使用的来源。
- S3 单次请求默认最多 **64 MiB**。大文件应按该上限分片上传，或通过正整数 `ORCAS_MAX_REQUEST_BYTES` 调高限制。此实现仍会将正文读入内存，应结合实际并发量配置。
- 在 TOML 的 `[server.http]` 中设置 `serverReadHeaderTimeout = "10s"`、`serverReadTimeout = "2m"` 可调整读取超时；缺失或非正数使用安全默认值。
- 使用 `Authorization: Bearer <token>`，迁移仍通过查询或表单参数传递令牌的调用方。使用旧的跳过验签配置的压测客户端必须改为正常签名。
- SDK 拒绝包含路径分隔符、父目录、绝对路径、Windows 驱动器或数据流形式的远端名称。旧密码哈希与原有压缩数据保持读取兼容。
- 新建文件采用私有权限，已有文件的权限不会被自动改写。管理员应检查旧存储目录、数据库和配置文件的访问权限。

`UNSIGNED-PAYLOAD` 仍按 S3 协议支持，此模式的传输完整性依赖 TLS。应用应在 HTTPS 入口部署；本次没有变更线上服务、账号密码或证书。

## 验证结果

在 macOS arm64、Go 1.27.3 下完成以下验证：

- 全包构建、全包测试编译与默认 vet 检查。本地最终复验使用 `-p 1 -ldflags=-w`，逐包链接并省略调试符号，以适应磁盘空间限制。
- 新增安全回归测试，含 SQL 排序注入、正文篡改、过期 JWT、上下文提权、权限撤销、旧哈希迁移、跨域与路径逃逸，并通过竞态检测。
- SDK 原有短测试、压缩格式兼容性回归、CI 选定的 VFS 元数据、密钥切换和写入安全回归通过竞态检测。
- CLI 冒烟验证：缺少引导密码时拒绝初始化、显式初始化成功、标准输入密码只读取一次、自定义数据库目录生效、已有数据库重启、错误密码被拒绝。
- `go mod verify` 通过。
- `govulncheck v1.9.0`：**可调用的已知漏洞为 0，导入包中的漏洞为 0**。仍有 1 条仅存在于依赖模块中的提示：`golang.org/x/crypto/openpgp` 已停止维护；本项目没有导入该包。

常用复验命令：

```sh
go build -mod=readonly ./...
go test -mod=readonly -run '^$' ./...
go test -mod=readonly -race -count=1 -timeout=5m ./core ./rpc/... ./s3/middleware ./sdk -run '^TestSecurity'
ORCAS_ADMIN_PASSWORD=orcas go test -mod=readonly -race -short -count=1 -timeout=5m ./sdk
go test -mod=readonly -race -count=1 -timeout=5m ./core -run '^TestCompression'
go mod verify
go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...
```

完整发布回归入口为 `scripts/ci.sh`，VFS 使用真实登录的临时测试管理员。脚本末尾会要求依赖文件与 Git 提交一致；本次有意更新了依赖文件，提交变更后该检查才会通过。

本次没有运行完整的历史集成、挂载及压力测试。它们的已有环境要求和已知问题见 [ci.md](ci.md)。本地磁盘不足曾导致编译、链接中断；清理可重建的 Go 编译缓存和可重新下载的工具链压缩包，并逐包重试后，上述检查完成。
